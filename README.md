# Аргус — СМР (Фронтенд)

Клиентская часть цифровой платформы мониторинга строительно-монтажных работ (СМР) и контроля применения строительной техники на объектах капитального строительства (ОКС) города Москвы.

Платформа обеспечивает автоматизированный контроль соблюдения директивных графиков, анализ присутствия и активности техники по видеопотокам, фиксацию технологических простоев и процессуальный арбитраж инцидентов.

---

## Стек технологий

* Ядро: React 19, TypeScript 5.3+
* Сборщик: Vite 6
* Управление состоянием и кэширование: Redux Toolkit, RTK Query
* Маршрутизация: React Router DOM 7
* Стилизация: CSS3 с CSS-переменными, PostCSS (postcss-sorting)
* Контейнеризация и сервер: Docker, Nginx (Alpine), Docker Compose

---

## Настройка переменных окружения

Перед запуском приложения создайте файл `.env` в корневой директории проекта:

```env
REACT_APP_API_URL=http://localhost:8000
CHOKIDAR_USEPOLLING=true
WATCHPACK_POLLING=true
```

Параметры:
* `REACT_APP_API_URL` — базовый URL бэкенд-сервера API.
* `CHOKIDAR_USEPOLLING` и `WATCHPACK_POLLING` — включение файлового поллинга для корректной работы Hot Module Replacement (HMR) внутри Docker-контейнеров на хост-системах Windows и macOS.

## Запуск приложения

### Вариант 1. Запуск через Docker Compose (рекомендуемый)

Сборка образов и фоновый запуск контейнеров:

```bash
docker compose up -d --build
```

Особенности сборки:
* Многоэтапный Dockerfile (Node.js 20 Alpine для компиляции бандла и Nginx Alpine для раздачи статики).
* Веб-сервер Nginx настроен на порт 3000, выполняет маршрутизацию SPA (fallback на index.html) и проксирует вызовы API и статических файлов на бэкенд (`host.docker.internal:8000`).

После запуска веб-интерфейс доступен по адресу:
```
http://localhost:3000
```

Остановка контейнеров:
```bash
docker compose down
```

### Вариант 2. Локальный запуск без Docker

Требования: Node.js версии 20+, npm версии 9+.

1. Установка зависимостей:
```bash
npm install
```

2. Запуск локального сервера разработки:
```bash
npm start
```
или:
```bash
npm run dev
```

Приложение будет запущено по адресу:
```
http://localhost:3000
```

## Описание разделов и функционала

### 1. Кабинет прораба (`/foreman`, `/foreman/:projectId`)

Предназначен для настройки календарно-сетевого графика, спецификации строительной техники и привязки камер.

* Автогенерация графика: развертывание стандартного состава технологических фаз (подготовительные, земляные, монолитные, фасадные работы и инженерные сети) по типовому шаблону техзадания.
* Управление сроками: прямое редактирование длительности подэтапов в днях с автоматическим каскадным пересчетом дат последующих связанных работ.
* Спецификация техники: привязка единиц техники к конкретным этапам с указанием количества и типа требования:
  * Обязательная (`Обяз.`) — техника, отсутствие которой в секторе производства работ фиксируется системой как критический дефицит.
  * Допустимая (`Допуст.`) — техника, присутствие которой разрешено регламентом без формирования алертов нецелевого нахождения.
* Критический путь: маркировка этапов, задержка которых напрямую влияет на итоговую дату ввода объекта в эксплуатацию (визуально выделяются красным цветом на шкале Ганта).
* Подключение камер: модальный менеджер добавления RTSP/HTTP-потоков для непрерывного видеоконтроля.
* Утверждение графика: пакетная синхронизация внесенных параметров и перевод графика из статуса `DRAFT` в рабочий режим `ACTIVE`. После утверждения редактирование графика прорабом блокируется.

### 2. Пульт инженера технадзора (`/engineer`, `/engineer/:projectId`)

Служит для непрерывного мониторинга, контроля рисков срыва сроков и процессуального арбитража нарушений.

* Оперативный мониторинг: дашборд готовности ОКС (процент физического выполнения и процент истекшего директивного времени), счетчики работающей и простаивающей техники, индикация текущего активного этапа.
* Светофорная система контроля:
  * Зеленый статус — штатный ход работ, критических отклонений нет.
  * Желтый статус — предупреждение о риске (простой техники или дефицит). Запускается регламентный таймер до автоматической эскалации.
  * Красный статус — критическое нарушение, требующее решения инженера.
* Арбитраж инцидентов: модальное окно выбора процессуального сценария:
  1. Сброс (Ложная тревога): отмена алерта инженером с внесением пояснения (технологический перерыв, особенности ракурса камеры), возвращение в штатный зеленый режим без санкций.
  2. Штрафной коридор (Оранжевый статус): фиксация вины подрядчика, назначение срока на ликвидацию отставания (от 1 до 168 часов), фиксация потерянных часов для расчета неустойки.
  3. Форс-мажор (Фиолетовый статус): фиксация внешних факторов (неблагоприятные погодные условия, ограничения городских служб), фиксация реквизитов подтверждающего акта. Сроки могут быть компенсированы без начисления штрафов.
* Каскадный сдвиг сроков: автоматический пересчет цепочки зависящих этапов вправо (задержка) или влево (опережение) с шагом от 1 до 180 дней. Все операции протоколируются в журнал аудита.
* Досрочная приемка работ (АОСР): фиксация досрочного закрытия подэтапа по акту освидетельствования скрытых работ с автоматическим закрытием всех предшествующих незавершенных этапов данной технологической цепочки.

### 3. Сводный реестр Департамента (`/admin/registry`)

Обеспечивает централизованный контроль за всеми строящимися объектами столицы.

* Сводный мониторинг: фильтрация объектов по статусам (штатный ход, штрафной коридор, форс-мажор), контекстный поиск по наименованию объекта, адресу площадки или текущему этапу СМР.
* Режим наблюдателя (Read-Only): переход представителя Департамента на страницу графика или в пульт инженера активирует режим чтения. Действия по сдвигу сроков, утверждению графиков, резолву алертов и управлению камерами блокируются для обеспечения сохранности данных.

### 4. Управление ОКС и правами доступа (`/admin/oks`)

Раздел администрирования структуры объектов и персонала.

* Регистрация ОКС: создание карточки объекта капитального строительства с валидацией длины полей (наименование — до 100 символов, адрес — до 160 символов) и выбором нормативного типа объекта.
* Управление системными ролями: назначение глобальных ролей (`foreman`, `engineer`, `admin`) зарегистрированным пользователям по их email.
* Формирование команд объектов: назначение конкретных прорабов и инженеров на объекты с возможностью оперативного отзыва полномочий.

### 5. Первичный доступ новых пользователей (`/`)

После самостоятельной регистрации аккаунта пользователь не получает доступ к данным ОКС. Профиль переходит в режим ожидания (`HomePage`), где отображается статус ожидания допуска и email сотрудника. Клиент осуществляет автоматическую фоновую проверку предоставления роли каждые 5 секунд.
