# 🏗️ Фронтенд «Аргус — СМР»

Веб-приложение цифровой платформы непрерывного объективного видеомониторинга строительно-монтажных работ (СМР) и контроля использования техники на объектах капитального строительства (ОКС) города Москвы.

---

## 1. Настройка окружения (`.env`)

Создайте файл `.env` в корне проекта фронтенда:

```env
REACT_APP_API_URL=http://localhost:8000
CHOKIDAR_USEPOLLING=true
WATCHPACK_POLLING=true
```

* `REACT_APP_API_URL` — базовый адрес REST API бэкенда.
* `CHOKIDAR_USEPOLLING` и `WATCHPACK_POLLING` — режим опроса файлов для бесперебойного Hot Reload внутри Docker на Windows/macOS.

---

## 2. Запуск проекта

### Вариант А. Запуск в Docker-контейнере

```bash
# 1. Сборка Docker-образа
docker build -t argus-frontend .

# 2. Запуск контейнера через Docker Compose
docker compose up -d --build
```

Приложение будет доступно по адресу: **`http://localhost:3000`**.

### Вариант Б. Локальный запуск (без Docker)

```bash
# Установка зависимостей
npm install

# Запуск приложения в режиме разработки
npm start
```

## 4. Функционал и разделы системы

### 4.1. Кабинет прораба (`/foreman`)
* **Автогенерация из шаблона ТЗ:** кнопка «Шаблон ТЗ» автоматически разворачивает утверждённые технологические этапы (земляные работы, монолит, фасад и т.д.).
* **Сроки и календарные дни:** длительность подэтапов регулируется прямо в ячейках ввода.
* **Распределение строительной техники:**
  * Добавление машин через выпадающий список `+ Добавить технику`.
  * Переключатель приоритета `Обяз.` / `Допуст.` (при отсутствии обязательной техники нейросеть фиксирует нарушение).
  * Регулировка количества единиц кнопками `+` и `-`.
* **Критический путь:** автоматическая подсветка ключевых этапов, определяющих дату ввода объекта (красная полоса на диаграмме Ганта).
* **Видеонаблюдение:** модальное окно «Видеокамеры» позволяет подключать RTSP/HTTP-потоки площадки (например, эмулятор `http://mock_camera:8081/frame.jpg`).
* **Утверждение графика:** сохранение правок (`bulkSync`) и перевод графика из `DRAFT` в рабочий режим `ACTIVE`.

### 4.2. Пульт инженера технадзора (`/engineer`)
* **Мониторинг в реальном времени:** оперативные показатели готовности ОКС, текущий этап СМР, таймер автоэскалации нарушений и статус работы техники (активна / простой).
* **Процессуальное решение по инцидентам:**
  * Детальный разбор сути нарушения на русском языке и статуса критического пути.
  * Кнопка «Принять решение по инциденту» открывает модальное окно с 3 регламентными сценариями:
    1. **Сброс (Ложная тревога):** фиксация причины ➔ алерт гасится, светофор возвращается в штатный зелёный режим.
    2. **Вина строителей (Штрафной коридор):** указание причины, установка дедлайна (24–48 ч) и подрядчика ➔ запуск Оранжевого статуса с начислением потерянных часов (`time_lost_hours`).
    3. **Форс-мажор:** фиксация внешних факторов (погода МЧС, перекрытия дорог, сети) ➔ запуск Фиолетового статуса без штрафов.
* **Каскадный перенос сроков:** расчет сдвига цепочки этапов вправо (задержка `+`) или влево (нагон `-`) с пресетами дней (1, 3, 5, 7, 14, 30) и сохранением в **Audit Trail**.
* **Досрочная приемка по актам АОСР:** закрытие этапа с автоматическим завершением всех предшествующих незакрытых подэтапов цепочки.

### 4.3. Сводный реестр Департамента (`/admin/registry`)
* **Фильтрация ОКС:** карточки быстрого среза по зонам надзора (Штатный зелёный, Штрафной оранжевый, Форс-мажор фиолетовый).
* **Поиск:** фильтрация объектов по названию, адресу и текущему этапу.
* **Режим наблюдателя:** при переходе на стройплощадку по кнопке «Открыть» активируется режим «Только чтение» — сверху отображается синий баннер с замком, а все кнопки изменения графиков и камер блокируются.

### 4.4. Управление ОКС и ролями (`/admin/oks`)
* **Создание ОКС:** форма регистрации новой стройки (название до 100 симв., адрес до 160 симв.) с выбором нормативного типа объекта по ТЗ.
* **Выдача системных ролей:** назначение прав пользователям по их Email (`Прораб`, `Инженер` или `Департамент`).
* **Назначение команды:** привязка сотрудников к конкретным стройплощадкам и возможность оперативного отзыва с объекта.

### 4.5. Доступ нового пользователя без роли
* При самостоятельной регистрации на `/register` пользователь создается без назначенных прав.
* До тех пор, пока Администратор в разделе `/admin/oks` не выдаст роль и не прикрепит сотрудника к объекту, доступ ко всем рабочим разделам системы автоматически блокируется.
