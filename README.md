#  Фронтенд «Аргус — СМР»

Веб-приложение цифровой платформы для непрерывного видеомониторинга строительно-монтажных работ (СМР) и контроля использования строительной техники на объектах капитального строительства (ОКС) города Москвы.

---

## 1. Настройка окружения (`.env`)

Создайте файл `.env` в корне проекта фронтенда:

```env
REACT_APP_API_URL=http://localhost:8000

CHOKIDAR_USEPOLLING=true

WATCHPACK_POLLING=true
```

* `REACT_APP_API_URL` — адрес REST API бэкенда.
* `CHOKIDAR_USEPOLLING` и `WATCHPACK_POLLING` — включают опрос файлов, благодаря чему Hot Reload корректно работает внутри Docker на Windows/macOS.

---

## 2. Запуск проекта

### Вариант А. Запуск через Docker

Соберите Docker-образ:

```bash
docker build -t argus-frontend .
```

Затем запустите приложение через Docker Compose:

```bash
docker compose up -d --build
```

После запуска приложение будет доступно по адресу:

**http://localhost:3000**

### Вариант Б. Локальный запуск без Docker

Установите зависимости:

```bash
npm install
```

Запустите приложение в режиме разработки:

```bash
npm start
```

## 4. Функционал и разделы системы

### 4.1. Кабинет прораба (`/foreman`)

Кабинет прораба предназначен для настройки графика работ, распределения техники и подключения видеонаблюдения.

* **Автогенерация из шаблона ТЗ**
  Кнопка «Шаблон ТЗ» автоматически добавляет утверждённые технологические этапы: земляные работы, монолит, фасад и другие.

* **Сроки и календарные дни**
  Длительность отдельных подэтапов можно изменять непосредственно в таблице графика.

* **Распределение строительной техники**

  * Добавление техники через кнопку `+ Добавить технику`.
  * Выбор приоритета: `Обяз.` или `Допуст.`.
  * Если обязательная техника отсутствует, система фиксирует соответствующее нарушение.
  * Количество единиц техники можно изменять кнопками `+` и `-`.

* **Критический путь**
  Ключевые этапы, которые напрямую влияют на дату завершения объекта, автоматически выделяются на диаграмме Ганта красной полосой.

* **Видеонаблюдение**
  Через модальное окно «Видеокамеры» можно подключать RTSP/HTTP-потоки со строительной площадки. Для тестирования используется, например:

  `http://mock_camera:8081/frame.jpg`

* **Утверждение графика**
  После внесения изменений данные сохраняются через `bulkSync`, а график переводится из состояния `DRAFT` в рабочее состояние `ACTIVE`.

---

### 4.2. Пульт инженера технадзора (`/engineer`)

Раздел предназначен для оперативного контроля состояния строительного объекта и работы с выявленными нарушениями.

* **Мониторинг в реальном времени**
  На экране отображаются готовность ОКС, текущий этап СМР, таймер автоэскалации нарушений и состояние строительной техники — активна она или находится в простое.

* **Работа с инцидентами**
  Инженер может открыть подробности нарушения и принять по нему процессуальное решение.

  Кнопка «Принять решение по инциденту» открывает три сценария:

  1. **Сброс (ложная тревога)**
     Инженер указывает причину. Алерт закрывается, а статус объекта возвращается в штатное зелёное состояние.

  2. **Вина строителей (штрафной коридор)**
     Указывается причина, дедлайн от 24 до 48 часов и подрядчик. После этого запускается оранжевый статус и фиксируется количество потерянных часов (`time_lost_hours`).

  3. **Форс-мажор**
     Фиксируется внешняя причина: погодные условия, перекрытие дорог, проблемы с инженерными сетями и т. д. После этого объект получает фиолетовый статус без начисления штрафных часов.

* **Каскадный перенос сроков**
  При изменении сроков система рассчитывает сдвиг связанных этапов:

  * вправо — задержка (`+`);
  * влево — нагон (`-`).

  Для быстрого изменения доступны пресеты: `1`, `3`, `5`, `7`, `14` и `30` дней.

  Все изменения сохраняются в **Audit Trail**.

* **Досрочная приёмка по актам АОСР**
  При закрытии этапа система автоматически завершает все предшествующие незакрытые подэтапы соответствующей цепочки.

---

### 4.3. Сводный реестр Департамента (`/admin/registry`)

Реестр позволяет быстро посмотреть состояние всех строительных объектов.

* **Фильтрация ОКС**
  Доступны быстрые фильтры по статусам:

  * 🟢 штатный зелёный;
  * 🟠 штрафной оранжевый;
  * 🟣 форс-мажорный фиолетовый.

* **Поиск объектов**
  Объекты можно искать по названию, адресу и текущему этапу строительства.

* **Режим наблюдателя**
  При открытии строительной площадки через кнопку «Открыть» включается режим «Только чтение».

  В верхней части страницы появляется синий баннер с замком, а функции изменения графика и управления камерами становятся недоступны.

---

### 4.4. Управление ОКС и ролями (`/admin/oks`)

Этот раздел используется для создания строительных объектов и управления доступом сотрудников.

* **Создание ОКС**
  Администратор может зарегистрировать новую стройку, указав:

  * название объекта — до 100 символов;
  * адрес — до 160 символов;
  * нормативный тип объекта в соответствии с ТЗ.

* **Выдача системных ролей**
  Роль пользователя назначается по его Email. Доступны роли:

  * `Прораб`;
  * `Инженер`;
  * `Департамент`.

* **Назначение команды**
  Сотрудники привязываются к конкретным строительным объектам. При необходимости сотрудника можно оперативно открепить от объекта.

---

### 4.5. Доступ нового пользователя без роли

Пользователь может самостоятельно зарегистрироваться через `/register`, однако сразу после регистрации у него нет рабочих прав.

Пока Администратор не назначит ему роль и не привяжет сотрудника к строительному объекту, доступ к рабочим разделам системы автоматически закрыт.

Таким образом, сама регистрация аккаунта не даёт доступа к данным строительных объектов.

## 5. Полезные команды разработки

### Проверка кода

Проверка TypeScript-кода и поиск ошибок:

```bash
npm run lint
```

Автоматическое исправление ошибок ESLint:

```bash
npm run lint:fix
```

### Работа со стилями

Сортировка CSS-правил:

```bash
npm run sort:css
```

Полное форматирование проекта:

```bash
npm run format
```

Команда запускает необходимые проверки и сортировку стилей.

### Сборка проекта

Для создания production-сборки:

```bash
npm run build
```

Готовая сборка будет помещена в папку `/build`.
