# Фронтенд «Аргус — СМР» — Инструкция и запуск

Веб-приложение для мониторинга строек, управления графиками Ганта, детекции техники и разбора инцидентов.

---

## 1. Настройка окружения (`.env`)

Создайте файл `.env` в корне проекта фронтенда:

```env
REACT_APP_API_URL=http://localhost:8000
CHOKIDAR_USEPOLLING=true
WATCHPACK_POLLING=true
```

## 2. Запуск проекта

### Вариант А. Запуск в одном Docker-контейнере

```bash
# 1. Собрать образ
docker build -t argus-frontend .

# 2. Запустить контейнер через Docker Compose
docker compose up -d --build
```

Примечание: Приложение будет доступно по адресу: `http://localhost:3000`.

### Вариант Б. Запуск локально (без Docker)

```bash
# Установка зависимостей
npm install

# Запуск приложения в режиме разработки
npm start
```

## 4. Как работают экраны приложения

### 1. Кабинет прораба (`/foreman`)

- Шаблон ТЗ: кнопка «Шаблон ТЗ» автоматически разворачивает утверждённые
  технологические этапы (земляные работы, монолит, фасад и т.д.).
- Сроки и дни: длительность подэтапов меняется прямо в инпуте с цифрами.
- Настройка техники:
  - Кнопка `+ Добавить технику` добавляет нужную машину.
  - Переключатель `Обяз. / Допуст.` меняет статус техники (при дефиците обязательной техники сработает алерт).
  - Кнопки `+` и `-` регулируют количество единиц.

- Критический путь: выпадающий список со стрелочкой `▼` рядом с названием подэтапа переключает статус: «Крит. путь» (красная полоса на Ганте) или «Обычный».
- Камеры: кнопка «Видеокамеры» вверху позволяет добавить RTSP/HTTP поток (например, `http://mock_camera:8081/frame.jpg` или `http://localhost:8081/frame.jpg`).
- Фиксация: кнопки «Сохранить правки» и «Утвердить график».

### 2. Пульт инженера технадзора (`/engineer`)

- Мониторинг ОКС: отображает карточки готовности, текущий этап СМР, таймер эскалации и статус техники (в работе / простой).
- Разбор инцидентов (Модалка):
  - Показывает понятный текст нарушения (например: «По графику требуется 1
    ед. («самосвал»), фактически зафиксировано: 0 ед.») и оценку риска из
    бэкенда.
  - Кнопка «Принять решение по инциденту» открывает окно с 3 сценариями:
    1. 🟢 Сброс (Ложная тревога) — инженер пишет причину ➔ алерт гасится,
       светофор возвращается в зелёный режим.
    2. 🟠 Вина строителей (Штрафной коридор) — инженер пишет причину,
       выставляет тайминг (например, `24 ч`) и подрядчика ➔ включается
       Оранжевый статус со счётчиком штрафных часов.
    3. 🟣 Форс-мажор — инженер указывает погодную причину / перекрытие дорог
       ➔ включается Фиолетовый статус (штрафы не начисляются).

- Каскадный перенос сроков: модалка каскадного сдвига этапов со знаками
  `+` (задержка) и `-` (нагон), быстрыми пресетами дней (`1`, `3`, `5`, `7`, `14`, `30`) и
  зафиксированными кнопками внизу.

### 3. Реестр Департамента (`/admin/registry`)

- Фильтры: карточки справа фильтруют ОКС по зонам (Штатный зелёный, Штрафной
  оранжевый, Форс-мажор фиолетовый).
- Режим наблюдателя: если админ нажимает «Открыть» напротив любого объекта, он
  переходит на стройку строго в режиме чтения — вверху висит синий баннер с
  замком, а все кнопки изменения графиков и камер надёжно заблокированы.

## 5. Полезные команды разработки

### Проверка TypeScript-кода линтером

```bash
npm run lint
```

### Автоматическое исправление ошибок ESLint

```bash
npm run lint:fix
```

### Сортировка правил во всех CSS-файлах (PostCSS Sorting)

```bash
npm run sort:css
```

### Полное форматирование проекта (линтер + сортировка стилей)

```bash
npm run format
```

### Сборка готовой статики для продакшна (в папку `/build`)

```bash
npm run build
```
